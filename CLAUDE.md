# CLAUDE.md

## Project Overview

BibCiTeX is being rewritten on the `native` branch:
macOS uses SwiftUI/AppKit, Windows uses C#/WinUI, and both call a shared Rust core.
The former desktop host and Web frontend have been removed. Verify the generated
bindings, Rust checks, and platform compilation. Distinguish compilation and unit
tests from GUI acceptance and signed update deployment.

## Architecture

- `crates/bibcitex-core/`: preserved BibTeX parsing, settings, search, and filters.
- `crates/xpaste/`: independent platform paste implementation.
- `crates/bibcitex-service/`: shared application operations, registry, search cache, and DTOs.
- `crates/bibcitex-ffi/`: Swift bindings generated by UniFFI 0.32.2.
- `crates/bibcitex-csharp/`: C# bindings generated by Interoptopus 0.16.5.
  Choose each platform independently; do not force a common binding library.
  Do not reintroduce a hand-written C bridge or JSON transport.
- Updates: Sparkle 2 on macOS; Velopack (unpackaged EXE/MSI) on Windows.
  Do not restore a shared Rust updater or invent publishing credentials.
- `macos/BibCiTeX/`: SwiftUI workbench, helper, models, and SVGs.
- `windows/BibCiTeX/`: WinUI workbench, helper, and platform services.
- `bindings/`: separate Swift and C# generators, invoked by the platform build graph.
- `macos/BibCiTeX.xcodeproj`: Xcode owns the app, resources and Rust/Swift target dependencies.
- `windows/BibCiTeX.sln`: Visual Studio/MSBuild owns Rust and C# code generation.
- `Justfile`: command aliases only; IDE builds must not require a prior Just invocation.
- `xtask/`: shared CI metadata and publication logic written in Rust, without Python.
- IDE builds must work from a clean checkout. Do not add Python or PowerShell to macOS build paths.
- `public/icons/`: external SVG icon assets, including Windows variants.
- `assets/app-icons/`: preserved app bundle assets.
- Root `Cargo.toml`: Rust workspace. Platform scripts are for the user to run.
- Shared crate versions and paths belong in root `[workspace.dependencies]`;
  member crates inherit them with `workspace = true`.

## Working Constraints

- Do not write or restore UI/GUI tests, including interface model, interaction,
  layout, control, and visual rendering regressions. Use compilation and non-UI
  core/integration tests; GUI acceptance is manual.

- The latest user instruction authorizes binding generation, compilation, tests,
  and Cargo clippy. Run them and fix failures; static parsing alone is insufficient.
- Do not launch/open GUI applications, publish, or locally package releases unless
  requested. CI may define the requested build and signed update release jobs.
- Do not add `rust-version` or a pinned Rust toolchain file. Use the available
  toolchain locally and stable Rust in CI.
- Preserve existing UI text; do not add unsolicited explanations to the UI.
- macOS UI icons prefer SF Symbols available on the running OS, falling back to
  the existing standalone SVG assets when a symbol is unavailable. Preserve brand assets.
- Windows UI icons remain standalone SVG files; never embed SVG/data URLs/icon fonts.
- Main windows and the Spotlight helper are all in scope on both platforms.
- Keep the helper compact. Do not restore the oversized idle search panel.
- Never commit or push unless requested. Preserve unrelated uncommitted work.
- Use `sb` to inspect source structure before reading function bodies.
- Report actual changed files with clickable absolute links in every final response.
- Act on authorized work immediately; do not ask again whether to proceed.

## Supported Bibliography Types

Article, Book, Thesis (Masters/PhD), Booklet, InBook, InCollection, Misc,
TechReport, InProceedings are supported by the preserved core. Manual,
Proceedings, and Unpublished remain incomplete.
